# VII 视觉效果交接清单

给接手实现的工程师（Codex）。VII（行星际）的玩法、数值和存档都已经完成并有测试；这份清单只列**需要新增或优化的画面表现**。每一项都写明它表现的是哪份数据、在哪里画、画成什么样、怎样算完成。玩法逻辑不要改：所有画面都是只读的。

## 0. 通用规则（每一项都要遵守）

- **只读**：绘制函数只读 `session.orbital`，不写任何状态、不调用购买或模拟函数。测试里会序列化前后比对。
- **光点只代表方舟**：`drawArkLight`（`src/ark-lights.js`）只能用来画方舟（停泊、飞行、驻地各一艘）。居民、驻地等级、设施、城市都**不能**用点状光点表示，改用小型剪影、条带、纹理或结构线。
- **确定性**：不要用 `Math.random`。需要随机感时用各文件里已有的 `noise(n)` 哈希，或从天体 id 派生种子。同一个 `time` 必须画出同一帧。
- **减少动态效果**：`reducedMotion` 为真时，时间固定为 0，所有动画静止；静态画面仍要表达出状态（例如已建成几段环）。
- **低饱和配色**：沿用现有地月的配色——深青灰背景、暖金高光（`#e6d6a4` / `#f1e2b0` 一类）、各天体自己的底色（`src/solar-config.js` 的 `color`）。不要引入高饱和的红、蓝、紫。
- **尺度**：航图（总览）里的元素要小，不能压过行星本身；独立世界页里的元素可以大一些，但仍是「从轨道望下去」的比例。
- **性能**：总览和世界页每帧都在重绘（约 30 fps）。每个效果的绘制成本要有上限：粒子数固定、不随时间增长；可以缓存离屏画布（参考 `planet-render.js` 的 `nightMask` 缓存）。
- **测试**：每项至少一条浏览器测试（`tests/solar-cases.js` 里 `test.browser` 的写法），检查两件事：状态不同 → 画面不同（`toDataURL` 比较）；减少动态效果下两个时刻画面相同。

## 1. 方舟的派出与抵达（最优先）

现在方舟只是一个沿弧线移动的光点，派出和抵达都没有过程感。

1. **派出**（总览 + 火星页）
   - 数据：`o.solar.flights` 中 `o.elapsed - f.departAt < 3` 的方舟。
   - 表现：火星旁停泊的那一排里，最末一点先亮起点火闪光（约 0.6 秒），沿切线脱离队列，剩下的光点平滑补位（不要瞬移）。
   - 火星页：在球体边缘外画出离港的方向。
2. **航行**（总览）
   - 数据：`flightLeg(o, f)` 给出当前这一段的起点、终点和进度。
   - 表现：光点后面拖一段 6–10 像素的渐隐尾迹。航线用虚线画出，走过的部分变淡。
   - 旧存档的方舟可能带有中转点（`f.via`），要按每一段分别画。
3. **抵达**（总览 + 目标世界页）
   - 数据：`o.elapsed` 接近 `f.arriveAt` 的最后 2 秒，以及驻地 rank 从 0 变 1 之后的 2 秒。后者没有存档字段，可以用「`facilities[key] === 1` 且该驻地没有更早的付款时间」近似；更好的做法是在 UI 层记住上一帧的等级。
   - 表现：减速闪光加一圈扩散的细环，然后光点进入驻地轨道，环绕天体缓慢运行。
4. **在目标世界页看到来船**
   - 数据：`o.solar.flights` 中 `f.body === 当前页天体` 的方舟。
   - 表现：从画面边缘沿一条弧线驶来，旁边用小字写抵达倒计时（与档案里的秒数一致）。
5. **文明转运**
   - 数据：`o.solar.transfers`。
   - 表现：地球 → 火星的转运方舟在总览上已有光点。抵达火星时，在火星页和穹顶剖面上画一道从天而降的细光，落进对应的穹顶户位，穹顶玻璃闪一下。

验收：派出、航行、抵达三个阶段在 `reducedMotion=false` 下帧帧不同；在 `reducedMotion=true` 下只显示终态（停泊、在途位置或驻地）。

## 2. 火星：穹顶、殖民与升格文明的开发

1. **火星球面上的穹顶**（之前那版太丑，已删除，需要重做）
   - 数据：`o.solar.talents.dome`（座数）、`householdsPerDome(o)`、`colonies.mars.civs`。
   - 表现：穹顶应是**极小**的高光：朝阳一侧是几个亮点般的玻璃反光，背阳一侧是穹顶里透出的暖色窗光（不是 `drawArkLight`）。位置固定在球面上，随自转移动；位于球的背面时不画。
   - 核冬天：反光变灰，窗光熄灭。
2. **穹顶剖面**（`dome-render.js`，已有，需优化）
   - 户位数要跟 `householdsPerDome(o)` 一致（冰水补给、土卫五会变成每座 3–4 户）。
   - 楼群的高度和窗光要按居民时代区分得更明显。
   - 正在抵达的转运：见 1.5。
   - 升格文明迁往轨道（太空电梯之后）时，它原来住的那一户要空出来，并能看出它上了电梯。
3. **升格文明的开发**（新机制，目前完全没有画面）
   - 数据：`colonies.mars.growth.step`（0–11）与 `progress`。步骤见 `GROWTH`：
     1. 大穹顶
     2. 地表探索
     3. 太空电梯
     4. 环火星生存空间 1–7 段
     5. 绿化火星
   - 火星页的表现：
     - **大穹顶**：几座小穹顶合成一座横跨的大穹顶。穹顶剖面里也要合成一座。
     - **地表探索**：从穹顶延伸出几条细细的车辙线和信标。
     - **太空电梯**：从赤道竖起一根细缆，顶端有一个小平台，随自转移动。
     - **环火星生存空间**：参考 VI 地球星环（`orbital-render.js` 的 `habitatSegments` 和绘制代码），按段数建成。建设中的那一段半透明，并有施工光。
     - **绿化火星**：锈红底色里一块块向外扩散的暗绿。按 `progress / seconds` 渐进，完成后覆盖中低纬度，不要把整颗星染绿。
   - 总览：火星建成星环后画一道细环；绿化后火星颜色偏一点绿。
   - 档案里的开发进度条已有，只需确保颜色一致。
4. **火星战争的实时画面**
   - 现在用 CSS `filter` 给战斗画布调成红色，效果很弱。
   - 改法：给 `drawBattleScene` 加一个可选的 `palette` 参数（天空、远山、地面三组颜色），火星用锈红的地面、淡粉黄的天空、两个小月亮（火卫一、火卫二），不画地球那样的月亮。
   - 地球的战斗画面不能受影响（`tests/` 里有像素级的战斗渲染测试，改完要全部通过）。
5. **核冬天**：现在只是一层灰色覆盖。改成：灰褐色的尘霾从一点扩散到全球，穹顶窗光熄灭，大气辉光变暗。倒计时结束时尘霾退去。
6. **大气改造**（`talents.terraform`，3 级）：火星外缘的大气辉光每级变厚一点。

## 3. 各行星的驻地和天赋画面

驻地从「等级光点环」改成**结构剪影**，等级越高结构越多。卫星驻地在对应卫星上画一个小结构。每颗星列出应画的内容：

- **水星**
  - 日冕阵列（能量板）：昼面上排成长条的反光太阳能板，数量 = 等级，随自转移动，只在受光面反光。
  - 晨昏线城市：沿明暗交界线移动的一小段暖色城市带。
  - 水星弹射轨道：一条细长的直线轨道，偶尔有一道射出的亮线划向远方。
  - 近日熔炉 / 铁核开采：昼面上一点橙色的熔炉辉光。
  - 日冕探测器：一个贴着太阳方向运行的小亮点，注意它不是方舟光点，要用十字形小探测器剪影。

  - 高空浮空城：云层上方漂浮的小城剪影（带气囊），数量 = 等级。

  - 轨道遮阳帘：金星与太阳之间一片极薄的半透明圆盘。
  - 雷暴捕能：云层里偶尔一闪的电光，频率低。
  - 大气提纯 / 碳纤维：不单独画。
- **小行星带**（`drawBeltScene`）
  - 采矿舰队：岩块间几艘采矿拖船剪影，旁边有碎屑火花；数量随等级增加。

- 已有驻地的天体旁画一个极小的「驻地」结构符号（不是光点），与飞来的方舟区分。

- 冥王星的轨道画成偏心的椭圆（现在是圆），并且比其他轨道更倾斜一点。

### 设施立体化修订

`structure-models.js` 集中生成并缓存微型几何，按面法线受光、深度排序与球面切向基投影；地面设施随自转转向，背面不可见。采集器、驻地、阵列、拖船和船坞使用实体舱体与薄板，玻璃穹顶用透明曲面。球面火星与聚落近景共用同一模型及真实户位；近景保留时代建筑、转运、谈判、战争和核冬天状态。星环有厚度和前后遮挡。新增模型近景校阅，不引入位图资产、框架或存档字段。

行星的明暗分界使用缓存矢量等光照带，解决旧低分辨率遮罩在首帧和后续帧之间的差异；地球渲染保持原有路径。设施与行星的主光方向均在画面右上方。

设施修订验证：Node 与模拟器 **317/317**，完整浏览器回归 **453/453**，最终几何调整后的 VII 视觉专项 **75/75**。手动查看 320 / 390 / 1100px 画面；桌面 Chrome 对完整开发的火星、木星、土星与穹顶近景各绘制 30 帧，平均每帧约 1.6–4.2ms（仅画布绘制，不代表实体手机帧率）。
